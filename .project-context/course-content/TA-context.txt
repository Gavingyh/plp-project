1. WHERE THIS MODULE SITS IN THE CERTIFICATE
 
The Graduate Certificate in Practical Language Processing (GC-PLP) has 4 modules:
- Module 1: Text Analytics (3 days) — THIS MODULE — preprocessing, document classification/clustering/topic modelling, information extraction
- Module 2: New Media and Sentiment Mining (3 days) — sentiment detection/classification, entity/aspect extraction (see companion context file)
- Module 3: Text Processing using Machine Learning (4 days) — DNNs for text mining, LLMs and transfer learning
- Module 4: Conversational UIs (4 days) — architecture, conversation flow, chatbots, speech processing
 
Class rules: attendance is tracked (NUS CAS daily / SSG twice-daily depending on enrolment type); in-class assessments (quizzes, workshop submissions) are compulsory and must be passed to sit the exam.
 
Module learning outcomes (by end of Text Analytics):
- Describe and follow the general text mining process to discover insights (relations, patterns, trends) from textual data
- Understand and apply techniques for major text mining tasks: information extraction, text categorization, clustering, topic modelling
- Understand the importance of domain-specific lexical/knowledge resources (vocabularies, thesauri, dictionaries, rules) and be able to build them to improve mining results
 
 
2. DAY-BY-DAY CONTENT
 
--- DAY 1 — Course Introduction + Intro to Text Analytics + Text Preparation ---
 
Course Introduction: certificate structure (see section 1), course agenda, class rules, GC-PLP overall learning outcomes.
 
Intro to Text Analytics:
- Definition: deriving insights/trends/patterns from unstructured text; converting unstructured text into structured (numeric) data
- Why text analytics: most business information is unstructured; formal/semi-structured/informal text sources
- Applications: customer experience management, brand monitoring, market research, fraud detection, healthcare records
- What text analytics can do: sentiment analysis, text classification (email routing, spam filtering, news filtering), feature generation to boost predictive models, document search, information extraction (QA, NER)
- The Text Analytics Process = CRISP-DM (Cross-Industry Standard Process for Data Mining), walked through in detail: (1) Business Understanding, (2) Data Understanding, (3) Data Preparation, (4) Modeling, (5) Evaluation, (6) Deployment — each phase's sub-tasks specific to text (e.g. corpus establishment, TDM construction, corpus annotation)
- Linguistic resources: dictionaries (valid-term, stopword/filter, synonym/substitution, domain terminology), corpora (validity vs reliability)
- Corpus annotation methodology: task/guideline definition, annotator training, self-agreement and inter-annotator agreement (IAA) checking
- IAA measures: Cohen's Kappa (formula given, with interpretation thresholds from Landis & Koch, Krippendorff, Green, Artstein & Poesio — 0.8 commonly cited as a good threshold), Fleiss's Kappa, Scott's Pi, Krippendorff's Alpha, F-measure (used when negative cases are numerous/undefined)
- LLMs as annotators: structured prompting (task description, labelling schema, guidelines, examples, output format), validation against human-verified data, human-in-the-loop correction
- Tool selection factors: business outcome, skill/time/budget, frequency of use, data privacy/cloud constraints, general vs domain-specific tools, vendor support vs open-source
- LLMs as a TA tool: versatile with proper prompting, but costly, heavy, and with data privacy/security caveats
 
Text Preparation (Module 3 of the deck — "Get the Text Data Ready for Analysis"):
- File preprocessing across formats: HTML, PDF, Word, Excel → TXT, XML, JSON (tag stripping, special character removal, zone detection, sentence/paragraph boundary detection)
- XML and JSON as structured exchange formats for tagged text (worked examples using a hotel review)
- Vectorization — Term-Document Matrix (TDM) path:
  - Preprocessing steps: tokenization (unigram/bigram/trigram), tokenization challenges (numbers with punctuation, abbreviations, apostrophes), vocabulary size and out-of-vocabulary (OOV) handling (traditional <UNK> token vs modern subword decomposition), case lowering (and its risks, e.g. "US"→"us"), stemming/lemmatization (inflectional vs derivational, named stemmers: Lovins 1968, Porter 1980, Snowball), stopword removal (functional words, domain-dependent stopword lists), punctuation/number removal
  - TDM indexing via bag-of-words; term weighting: binary, frequency-based, normalized frequency (adjusting for document length), tf-idf (formula: tf-idf = tf × idf, idf = log(N/df))
  - Frequent word lists and word clouds as quick corpus overviews; contrasting two groups (e.g. "like most" vs "like least")
  - Sparse matrix storage (row as list of (column, value) pairs)
- Vectorization — Embeddings path:
  - Word embeddings as dense low-dimensional vectors learned by DNNs during a prediction task (Word2Vec 2013, GloVe 2014, FastText 2016)
  - Lookup embeddings (one word = one vector; pro: captures semantic/linguistic info; con: can't handle polysemy) vs contextualized embeddings (BERT/GPT2-style; one word can get different vectors depending on context, e.g. "table" as furniture vs data structure) — contextualized preferred for tasks needing word-level representation like information extraction
  - Document embeddings: averaging/summing word vectors, or dedicated document-vector models (doc2vec, skip-thought, FastSent, Sentence-BERT)
- Workshop notebooks: step-by-step preprocessing walkthrough, DTM generation, embeddings exercise
 
--- DAY 2 — Text Categorization + Topic Modelling/Clustering (incl. LDA, SVD) ---
 
Text Categorization module:
- Definition and contrast with manual library cataloging (slow, tedious, inconsistent)
- Hard classification (mutually exclusive categories, e.g. spam/not-spam) vs soft classification (multi-label, e.g. news sections)
- Applications: subject categorization, spam detection, medical diagnosis, language ID, fraud/anomaly detection, sentiment analysis, news monitoring
- Two phases: Training (70/30 train/test split, train to comfort level, evaluate on test set) and Running (production use, periodic audit against human assessor)
- Classifier types: hand-coded rule classifiers (disjunctive normal form conditions); generative — Naive Bayes (full derivation: P(c|d) via word-likelihood product, worked sentiment example); discriminative — Decision Trees (worked name-gender example), Rocchio classifier (profile-vector similarity), Support Vector Machines (hyperplane separation, max-margin)
- Evaluation in depth: accuracy vs a reference/"gold standard" (which is itself imperfect); confusion matrices (multi-class and 2x2); precision & recall definitions; worked business scenarios showing why raw accuracy is misleading — a courtroom framing (false positives = convicting the innocent, false negatives = letting the guilty go free) and a fraud-detection cost-benefit calculation comparing two classifiers' net financial outcome (not just accuracy)
- Practical classifier issues: overfitting (train-set performance vs real-world performance divergence, illustrated with confusion-matrix pairs), hard vs soft (ranked/probabilistic) categorization for human-assisted decisions (e.g. medical diagnosis), aggregating multiple classifiers (union/intersection/voting/confidence-weighted)
- Unsupervised text categorization — Document Clustering: grouping documents by similarity to explore data (natural groupings, cluster count trade-offs, no training phase needed, language-independent)
- Dimensionality Reduction — SVD: sparsity/high-dimension motivation, A = UΣVᵀ (U/V orthogonal, Σ singular values sorted by importance), reducing dimensions before clustering (worked numeric example in a companion file, svd_example.pdf, computing singular values/vectors of a 2x3 matrix by hand)
- Topic Modeling: supervised vs unsupervised categorization framed as observed-vs-latent variable models; "topics" as latent discourses generating word bunches; animated TDM-based topic discovery (predefine topic count, output = word-topic and doc-topic distributions); applications — diachronic analysis (e.g. campaign vs governing speeches), contrastive analysis across sources
- Companion deck "LDA and others.pdf" (external academic slide deck, Levandoski & Lobo, CS3750, 2018) covers the full math: Vector Space Model and LSA via SVD (strengths: unsupervised, captures synonymy; limitations: no probabilistic model, can't handle polysemy) → probabilistic LSA/pLSA (aspect model, joint probability P(d,w), EM fitting E/M-step formulas, HITS/pHITS for authoritative-document detection, joint pLSA+pHITS model) → pLSA limitations (overfitting, no generative model for new documents) → Latent Dirichlet Allocation (LDA): Dirichlet distribution as prior, generative process (choose document length → per-document topic mixture θ ~ Dir(α) → per-word topic z ~ Multinomial(θ) → word w ~ p(w|z,β)), plate notation, exchangeability assumption, variational inference for approximate posterior computation, parameter estimation via variational EM, Dirichlet smoothing; topic model applications beyond text (information retrieval, computer vision "visual words", bioinformatics, network modeling); tooling: gensim (Python), MALLET (Java), topicmodels (R), Stanford Topic Modeling Toolbox
- Workshops: Day 2 AM — building and evaluating supervised classifiers (Naive Bayes/logistic regression/SVM/ensemble) on a "Human or Bot" (HorB) generated-review classification task; Day 2 PM — LDA/clustering workshop producing aspect-level topic clusters and word clouds from a large review dataset (2007-2009 reviews)
 
--- DAY 3 — Information Extraction ---
 
- IE defined: automatic extraction of pre-specified information (entities, events, relations) from text; automatic population of a structured template/table from free/semi-structured/unstructured text
- Concept hierarchy: Named Entity (lowest level — specific proper noun) → Concept (abstraction/natural class) → Information (anything answering a need, often with regular patterns) → Entity/Attribute/Fact/Event distinctions
- IE vs Information Retrieval vs Question Answering (IR returns documents to read; IE/QA return the answer directly) — illustrated with a worked "Pope election" example and an exercise identifying/categorizing concepts from a real NUS press-release-style paragraph
- Named Entity Recognition (NER): persons, organizations, locations, money, dates, times, percentages
- Relation Extraction: binary relations (child-of, employee-of, part-of, is-a), RDF triple representation (subject-predicate-object)
- Event Extraction: domain/task-specific, usually verb-anchored, includes event coreference and temporal expression extraction/timeline construction
- Worked exercise: filling a structured template (Occurrence/Event/Location/Dates/Method/Perpetrators/etc.) from a real news narrative (Boston Marathon bombing report)
- Main IE system components (pipeline): tokenization → morphological/lexical analysis (POS tagging, word-sense disambiguation) → syntactic analysis (shallow parsing/chunking, deep parsing) → domain analysis (coreference resolution, integration)
- Component detail:
  - Tokenization: language-specific challenges (word segmentation in Chinese, morphology in German/Hebrew, word composition in Thai)
  - POS tagging: ambiguity rates (14-15% of vocabulary, 55-67% of running tokens); Brill's rule-based transformation tagger; stochastic taggers (CLAWS, Viterbi, Baum-Welch, HMM-based)
  - Sequence labeling with HMM: transition probabilities (A) and observation likelihoods (B); Viterbi decoding
  - Shallow parsing/chunking (IOB-style phrase labeling) vs full/deep parsing (syntax trees, typed dependencies) vs semantic role labeling
  - Parsing challenges: robustness to ill-formed input, ambiguity/combinatorial explosion, efficiency
  - Word Sense Disambiguation and WordNet: synsets, lexical relations (synonymy, antonymy), semantic relations (hyponymy/ISA, meronymy/part-whole); WordNet applications (WSD, semantic distance, cross-lingual IR, QA, MT, categorization)
  - Coreference resolution: identity relations, anaphora (pronouns), proper-noun coreference, definite descriptions (e.g. "the fastest man in the world" = Usain Bolt) — worked example with a biotech-company news passage
- Approaches to building IE systems:
  - Rule-based: hand-coded (linguist-authored, iterative, slow but high quality) vs induced/ML-derived rules vs hybrid; rule form Match(pattern)→Do(action); lexical pattern matching (left-context+filler+right-context); worked CoreNLP TokensRegex example (company-name recognition); full regex operator reference (., ^, $, \d, \D, \w, \b, |, (), ?, *, +, [...], {n}, {n,m}) with an email-address pattern worked end-to-end
  - Machine-learning based: requires large well-annotated corpora, doesn't transfer well across domains; NER as sequence labeling/token classification (IOB/IO tagging); typical features (word + neighbors, POS, chunk label, gazetteer membership, prefix/suffix, word shape, hyphenation)
  - Popular sequence models compared: HMM (simple, joint probability), CRF (conditional probability, considers a window of surrounding tokens), similarity-to-dictionary algorithms (good for jargon/terminology), SVM
  - DNN-based IE: RNN/Bi-LSTM/Transformer sequence labeling, extractive QA (span selection from context, worked Eiffel Tower example), strong results via transfer learning/fine-tuning
  - LLMs for IE: instruction-tuned zero-shot generation, prompt engineering, handles standard NER well and extended info types with explicit prompting/schema; emerging libraries (LangExtract by Google, LLM-Aix for medical text anonymization); challenges — hallucination (needs source grounding for verifiability), inconsistent proficiency across languages, high operational cost/API limits
- Workshops: WordNet exploration, POS tagging, NER
 
 
3. THE RUNNING MINI-PROJECT (case study spanning all 3 days)
 
Title: "Mining Accident Reports" — text mining on real OSHA (workplace safety authority) accident report narratives (dataset: osha.txt, ~7.9MB, tab-delimited ID/Title/Text records).
 
Business framing: employers must report serious workplace injuries/deaths; the reports help employers, workers, and regulators assess workplace safety and target hazard reduction.
 
Questions the mini-project answers (mirroring the CRISP-DM process taught on Day 1):
1. What are the major types of accidents reflected in the reports?
2. Which type of accident has the largest number of occurrences?
3. Which part of the human body is injured most often?
 
Structured across the 3 days:
- Day 1: data understanding & exploration (record/field counts, report and title length via tokenization, data quality checks via token-count anomalies, rough content overview via word-frequency distribution) — this is a direct application of Day 1's CRISP-DM "Data Understanding" phase and TDM/tokenization content.
- Day 2: answering Q1 and Q2 (accident type identification and ranking) — applies Day 2's classification/clustering/topic-modelling content (the Day 2 PM workshop's aspect-clustering/word-cloud output over a large review-style dataset follows the same pattern).
- Day 3: answering Q3 (body-part-injured extraction) — applies Day 3's information extraction / NER content to pull structured entities (body parts) out of free-text narratives.
