# Overnight loop: fix and validate the chatbot answers branch (started 2026-10-04)

Resume this if a session ends mid-loop. Read it all, then check the "State" section against `git log` and the workflow journal before acting.

## Goal

Keep fixing the branch `fix/chatbot-answers` and re-validating it until a round ends with no confirmed high or medium finding, then run one live check (below) and stop. Never merge or push: the project owner decides that in the morning.

## Hard rules

- Stay on `fix/chatbot-answers`. No merge, push, rebase or amend. Stage by path; never `git add -A` or `git add .`.
- Never edit `dashboard/`, `.env`, `CLAUDE.md`, `CLAUDE.local.md`, `.claude/`. Never write to `data/plp.db`.
- Never stage `data/logs/*`, `data/README-teams.md`, or the untracked `data/eval/chatbot_eval_results_{reader,reader2,reader3,final,mix}_v2.jsonl` (CNA text).
- Never use ports 8501 or 8000. One Ollama job at a time; the validation agents must not use Ollama.
- Tests: `HF_HUB_OFFLINE=1 .venv-plp/bin/python3 -m pytest -q -p no:cacheprovider --deselect tests/test_scripts.py::test_stop_is_idempotent --deselect tests/test_scripts.py::test_start_refuses_a_port_it_does_not_own` (the two interact with the running API).
- Don't change the Grounded chatbot claim's wording in `CLAUDE.md`: that is the owner's or the team's decision.

## Tools (all in `data/run/overnight/`, ignored by git)

- `chatbot-fix-validate-round.js`: the round workflow. Run with `Workflow({scriptPath: "/Users/gavin/Projects/plp-project/data/run/overnight/chatbot-fix-validate-round.js", args: {...}})`. Args: `round` (number), `validation_file` (the latest docs/validation report), `fixes` (numbered list of confirmed findings with severities and locations), `guidance` (design notes for the fixer). To validate a commit already made, pass `skip_fix: true` and `fix_summary: {commit, fixed: [...], not_fixed: [], recorded_limits: [], tests, replay, design_notes, xfail_left: []}`.
- `replay_flags.py` (figure and citation checks over recorded answers; known differences: reader_v2 thin-2, llama8b_v2_intent and _intent_strip consensus-1), `fix_lines.py` (diagram line references), `timed_eval.py` and `ui_questions.py` (live runs), `readability.py`, and the timing and answer files the evidence page cites (`times_*`, `ab_*`, `ui_*`, `eval_*.log`).

## After each round

1. Read the workflow result: fixer summary, reviewer, tester (claims and step 3), auditor, triage.
2. Decide the triage's judgment items yourself. Claim results: a claim is DISPROVEN if any confirmed finding contradicts it.
3. Write `VALIDATION.md` (one screen, the /validate format) and the same text to `docs/validation/2026-10-04-chatbot-answers-<round word>-check.md` (sixth, seventh, ...). The next fixer stages it.
4. Update the "State" section below.
5. If confirmed high or medium findings remain, start the next round with them as `fixes`. If only low findings or owner decisions remain, stop the loop and do the live check.
