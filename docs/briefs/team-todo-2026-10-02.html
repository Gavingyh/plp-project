The corpus aspect run: when it has to be redone

llama3.1:8b is giving each of the 44,345 sentences one aspect, saved to data/aspect_llm/llama3.1_8b.96efe244.jsonl; nothing in the database changes. The answers are only good for the exact question the model was asked, so changing that question means starting again, which takes the MacBook about a day.

Sat middaythe current run finishesIf the Mac stays awake and plugged in.
~1 dayfor a full redoAll 44,345 sentences again. Longer if other jobs run on the Mac at the same time.
<1 hto test a new wording firstThe 1,277 labelled sentences, scored against the human aspects.
Nothinglost on a stop or crashThe same command resumes, and new data only adds its own sentences.

Redo from scratch when

  • an aspect is added, removed or renamed in config/aspects.yaml
  • an aspect's definition or a worked example changes: DEFINITIONS and EXAMPLES in aspects/llm_classify.py are the prompt
  • the model changes

The code notices all three by itself and starts a new file.

No redo for

  • a stop, crash or reboot: the same command resumes where it stopped
  • new sentences: only they are classified
  • the scoring model, NER and DBS Vickers, passing mentions (O5), chatbot settings, how the index is blended (O2)

Fixed on 2 Oct: the cache file is named by a hash of the prompt (96efe244 is today's wording). Before, a reworded prompt silently reused the old answers, so a "new" score was really the old one. Now a changed wording starts a new file, the old answers stay in theirs, and undoing the change picks the old file up again. Each run prints the file it uses.

To try a new wording:

  1. Stop the current run or let it finish: two jobs on the Mac's GPU slow each other.
  2. Edit the definitions or examples in aspects/llm_classify.py.
  3. Test, under an hour: .venv-plp/bin/python3 -m aspects.llm_classify --eval. Compare with 0.729 top-1 and wealth F1 0.50 today.
  4. Better: redo the corpus, about a day, with caffeinate -i .venv-plp/bin/python3 -m aspects.llm_classify --corpus --model llama3.1:8b. Not better: undo the edit; the old answers are used again.

A redo started by Fri 9 Oct still finishes before the 12–18 Oct re-score week. While it runs, other local-model jobs (chatbot evaluations, the judge) share the Mac: running them alongside slows both and has caused timeouts.

By Monday 5 October

The aspect decision starts the critical path; the rest of this week's items are quick or unblock labelling.

  • Run the LLM aspect classifier on the whole corpus, and choose the disagreement rule Decision by 5 Oct

    Why: the database's aspects come from seed centroids, which give a sentence about 6.4 aspects and match the human's aspect only 41% of the time; llama3.1:8b matches 73%, and 84% where qwen3:4b agrees. On an 11,000-sentence preview, switching separates the aspects: under centroids every aspect of every bank is positive; with the LLM, retail banking turns slightly negative for all three banks and DBS asset quality falls from +0.27 to +0.07. Every per-aspect claim in the report depends on this. Choose with it what happens to the 24% of sentences where the two models disagree: keep llama's answer, or mark them other.

    Unblocks: the re-score. The corpus run is already under way and finishes around midday on 3 Oct. Source: llm-aspect-classifier, index-preview.
  • Wealth or retail for priority-banking products, and whether the classifier's wording follows Decision best by 3 Oct

    Why: DBS Treasures, OCBC Premier and unit trusts bought at a bank are the boundary behind 63 of Opus's aspect disagreements, and wealth is one of the classifier's weakest aspects (F1 0.50). "By product" (recommended) is already close to the classifier's wording: premier and private banking are wealth; cards, savings accounts and fees are retail. It doesn't name unit trusts or other investment products, so adding them is a small edit to test (under an hour) before deciding on a redo. "By customer" changes the definitions, so the corpus run has to be redone: about a day of the MacBook. The current run finishes around midday on Sat 3 Oct; if the team leans to "by customer", saying so before then and stopping the run saves the rest of it. Changing only the labelling guideline needs no redo, but the classifier is then scored against labels that follow a different rule on that boundary.

    Decision 5 in the decision brief (due 5 Oct). Run times and steps: "The corpus aspect run" above. Source: llm-aspect-classifier, opus-labeller.
  • Decide whether to relabel the 299 test rows blind Decision by 5 Oct

    Why: the test labels match the suggestion model's label on 89% of rows, and each annotator's "blind" labels are identical to their labels made with the suggestion visible. Every test score inherits that anchoring, and it is the first threat to validity an examiner will raise. If the team relabels, it has to happen before the 12–18 Oct re-evaluation to count.

    Source: annotation-agreement (27 Sep), examiner assessment, threat 1.

    Source: chatbot-eval-build, "Second round".
