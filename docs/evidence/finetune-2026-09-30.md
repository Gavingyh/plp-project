# Fine-tuned FinBERT against the baselines

The first training of the deep-learning deliverable: FinBERT fine-tuned for
aspect-conditioned sentiment (sentence plus aspect in, three classes out) on
the 2026-09-27 labels ([agreement](annotation-agreement-2026-09-27.md)),
evaluated on the frozen random test split against base FinBERT zero-shot, a
lexicon and a classical baseline. Run on 2026-09-30 on this machine (Apple
MPS), after the labels were cleaned of duplicated pairs and train/test
leakage (`python -m train.labels`).

```bash
for seed in 42 1 7; do
  HF_HUB_OFFLINE=1 .venv-plp/bin/python3 -m train.finetune --seed $seed
  HF_HUB_OFFLINE=1 .venv-plp/bin/python3 -m train.evaluate --model-dir models/finbert-absa/seed_$seed/final
done
```

Setup: `ProsusAI/finbert`, learning rate 2e-5, batch 16, 4 epochs, 10%
warm-up, class-weighted loss, best epoch by dev macro-F1. 978 train/dev rows
split 85/15 (831 train, 147 dev) by seed; 299 test rows.

## Result

| model | test macro-F1 | test accuracy |
|---|---|---|
| **base FinBERT, zero-shot** | **0.571** | 0.70 |
| fine-tuned FinBERT, 3 seeds | **0.547 ± 0.013** (0.534, 0.560, 0.548) | 0.56–0.60 |
| TF-IDF + logistic regression | 0.514 | 0.57 |
| VADER lexicon | 0.427 | 0.49 |

**Fine-tuning did not beat base FinBERT on macro-F1.** The gap, 0.024, is
about two seed standard deviations. It is a reportable result: 831 training
rows is small for a 110M-parameter model, and the plan expected this risk.

It changes *what* the model gets right, which matters for this project:

| class (n) | base FinBERT F1 (recall) | fine-tuned, seed 7, F1 (recall) |
|---|---|---|
| negative (39) | 0.30 (0.21) | 0.44 (0.54) |
| neutral (166) | 0.78 (0.91) | 0.59 (0.49) |
| positive (94) | 0.64 (0.53) | 0.61 (0.73) |

Base FinBERT calls most sentences neutral and finds one negative sentence in
five. The fine-tuned model finds more than half of them, at the cost of
calling many neutral sentences positive or negative. Seeds 42 and 1 show the
same pattern (negative F1 0.42 and 0.41). For an investor dashboard that
under-reports bad news, that trade is arguably the more useful one, but it is
a judgement for the report, not something macro-F1 settles.

## Things to try before concluding

- **Training was still improving when it stopped.** Dev macro-F1 rose at
  every epoch for every seed (seed 42: 0.41, 0.58, 0.66, 0.67), so 4 epochs
  is probably too few; early stopping never triggered.
- **The dev set is small** (147 rows), so the best-epoch choice is noisy.
  k-fold cross-validation (the plan's fallback) would use the labels better.
- **The aspect input is weak.** Most rows are `retail_banking_sentiment`, and
  the aspect was corrected by people on 86% of rows, so the model sees an
  aspect distribution the corpus assignment will never produce.

## Earlier run, for comparison

The workstream's own Colab run on 2026-09-27 (seeds 42 and 1, before
cleaning) reported 0.534 and 0.510 against base FinBERT's 0.565. Their two
models, evaluated on the cleaned test set here, score 0.541 and 0.502, so the
five leaked sentences and the duplicates did not materially change the
picture. Seed 7 was trained then but not evaluated or kept.

## Caveats that apply to every number above

- The test labels were not independent of the LLM's suggested label
  ([agreement](annotation-agreement-2026-09-27.md)). Neither base FinBERT nor
  the fine-tuned model is that LLM, so the comparison between them stands.
- 39 negative test rows: one more or fewer correct moves negative F1 by
  about 0.02.
- Models are in `models/finbert-absa/seed_*/final` (gitignored, ~440 MB
  each). The corpus is still scored by base FinBERT; re-scoring with a
  fine-tuned model is a team decision (PLAN section 5).
